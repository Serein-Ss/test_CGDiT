# 实验目的

在不修改旧 MP20 基础生成模型权重的前提下，验证当前 `uv` CUDA 环境和新增 RL 基础设施能否在调度 GPU 上完成模型加载、结构采样、轨迹重放、PPO/GRPO 参数更新、PIRL 配对验收以及内部 H2/多保真接口调用。

本实验只验证代码链路，不验证真实材料性质提升。

# 输入与条件

- 生成模型：`output/singlerun/2026-06-27/00-32-50-mp20_base`
- 检查点：`epoch=869-step=737760.ckpt`
- 数据集：MP20 测试数据
- 随机种子：42
- 提交脚本：`submit_python/zrs_gen_rl_smoke.slurm`
- 执行入口：`scripts/cli/training/legacy_rl_gpu_smoke.py`
- 运行环境：Python 3.10、PyTorch 2.4.1+cu124、CUDA 12.4

# 执行内容

1. 加载旧 MP20 checkpoint 和测试批次；
2. 运行 20 步短轨迹并检查轨道元素一致性；
3. 对一个真实测试结构执行完整 999 次反向扩散更新；
4. 重放选定 transition，分别执行一次 PPO 和 GRPO 反向传播及 Adam 更新；
5. 使用共同随机数运行一次 PIRL 新旧策略配对接口；
6. 调用通道—时间信用分配接口；
7. 调用 predictor→MLFF→DFT 多保真预算选择接口。

# 结论边界

- PIRL、H2 和多保真结果使用合成接口信号，不能解释为真实材料性质改善；
- 当前没有接入正式 reward predictor 和独立 evaluator；
- 当前没有执行真实 MLFF 松弛或 DFT 计算；
- 该结果只能解除 GPU/采样/反向传播接口阻塞，不能解除正式 RL 训练的科学评价阻塞。
