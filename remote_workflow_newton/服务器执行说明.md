## 2. GPU冒烟与并发验证

脚本已在仓库 `remote_workflow_newton/` 中，无需手动上传到根目录。

```bash
python remote_workflow_newton/run_4g_6p.py all --dry-run
python remote_workflow_newton/run_4g_6p.py preflight
python remote_workflow_newton/run_4g_6p.py smoke
```

preflight验证原始输入哈希、CUDA可用性、GPU scatter反向传播和相关测试。
smoke对四个生成器、FE预测器、BG预测器各执行一个epoch、两个训练/验证/测试batch，随后生成一个联合条件结构；预测器测试输出必须有限。
它使用真实GPU，不用会强制CPU的 `fast_dev_run`。第一次会预处理完整CSV以重建缓存，预处理耗时不等于训练耗时。
任何一步失败先检查日志；不能只凭conda list认定环境可训练。
采样文件旁保存.diagnostics.json，检查坐标/长度/角度是否有限。短程未收敛权重可能产生Inf/NaN，本地联合模型已出现这一情况；脚本会警告，不能将CLI退出0当作有效生成通过。该诊断不以一个epoch的生成质量替代正式训练后结构评价。

需要同时训练两个任务时，先执行：

```bash
python remote_workflow_newton/validate_concurrency.py
cat output/newton_4g_6p_20261003/concurrency_validation.json
```

也可把验证本身提交到后台，完成后先查看报告，再启动正式训练：

```bash
mkdir -p logs
nohup python -u remote_workflow_newton/validate_concurrency.py \
  > logs/newton_validation.log 2>&1 < /dev/null &
echo $! > logs/newton_validation.pid
tail -f logs/newton_validation.log
```

前台和后台验证命令选一种执行。验证器不启动正式长程训练。

验证器先执行串行preflight/smoke，随后选64个20原子训练结构构造压力数据，顺序和两路并发各训练两个联合生成器、FE/BG预测器，每次两epochs并完成最佳checkpoint测试。
压力数据的train/val/test重复，仅用于代码和资源验证，不能当成科学评价结果。
报告记录串行/并发耗时、显存最小余量、可用RAM最小余量、退出状态及推荐并发数。
检查RAM时同时考虑Linux容器cgroup上限，默认要求显存余量至少2 GiB、RAM余量至少4 GiB。
显存压力按MP20的20原子上限构造，但子集RAM小于正式全量数据；正式并发训练继续监控RAM和显存，余量不足会停止本批训练进程，保留checkpoint。
短冒烟不能保证长程训练绝无OOM；两路并发也未必更快，只有报告speedup大于1.05才推荐两路。

## 3. 一次启动全部阶段

验证通过后：

```bash
mkdir -p logs
nohup python -u remote_workflow_newton/run_4g_6p.py all > logs/newton_4g_6p_pipeline.log 2>&1 < /dev/null &
echo $! > logs/newton_4g_6p_pipeline.pid
tail -f logs/newton_4g_6p_pipeline.log
```

默认训练和GPU生成顺序执行。Linux使用文件锁阻止重复启动同一run-id。
若需要分阶段执行，可用 `train`、`generate`、`evaluate` 替换 `all`。

若并发验证通过，且报告推荐两路，则改用：

```bash
nohup python -u remote_workflow_newton/run_4g_6p.py all --parallel 2 \
  > logs/newton_4g_6p_pipeline.log 2>&1 < /dev/null &
echo $! > logs/newton_4g_6p_pipeline.pid
```

这提交一个后台管理进程，由它最多同时运行两个训练任务。不能同时启动串行和并发命令。
生成和评价阶段仍顺序执行，避免训练、采样、评估同时抢GPU及内存。
并发训练的日志是logs/job0.log等；parallel_jobs.json给出编号与任务对应关系，parallel_training.json保存资源及完成情况。

## 4. 实验矩阵与默认预算

- 生成器：base、FE、BG、FE+BG，训练seed均为42；每组从头训练，上限1000 epochs。
- 预测器：独立M3GNet FE、BG，各seed=42/123/3407，上限300 epochs，使用既定早停配置。
- 训练batch=32，验证/测试batch=16，32位精度，单GPU；预处理worker=4。
- 条件评估目标：FE=-1.5 eV/atom，BG=2.0 eV，CFG=2.0；这些只是固定比较目标，不代表扫描了全部目标空间。
- 模板生成：四个模型的无条件采样，再加三个模型的性质条件采样，共7组。
- 随机原型生成：base无条件，其他三个采用相应条件，共4组；使用经验原子数先验，max_atoms=20。
- 每组4096个结构，生成seed=42，batch=32，共11组、45056个结构。
- 三对FE/BG预测器分别评价同一批生成结果，共33个“生成组×预测器seed”组合。

随机原型生成使用原子数统计先验，源码的空间群选择仍为随机抽取；这里不是DFT第一性原理计算。

## 5. 输出位置

```text
output/newton_4g_6p_20261003/
├── workflow.json                    # 源码commit与实验设置
├── environment.txt                  # preflight通过后的实际pip环境
├── logs/                            # 每个阶段的完整日志
├── smoke/                           # 小规模链路验证，独立于正式结果
├── generators/
│   ├── mp20_base/
│   ├── mp20_fe/
│   ├── mp20_bg/
│   └── mp20_fe_bg/
├── predictors/
│   ├── fe/seed42、seed123、seed3407/
│   └── bg/seed42、seed123、seed3407/
└── summaries/
    ├── predictor_test_metrics.csv
    └── seed42、seed123、seed3407/
```

模型目录保存hparams.yaml和验证损失选择的最佳checkpoint；成功完成训练及最佳checkpoint测试后才写 `.complete`。
每个生成器的 `generated_structures/` 保存生成PT文件，`evaluations/` 保存结构指标、逐结构性质预测、性质指标和来源清单。
预测器的test_preds.npy与test_targets.npy来自最佳checkpoint；汇总表计算测试MAE/RMSE。
上游性质汇总文件名仍叫 `seed42_property_summary.csv/json`，但目录和 `predictor_label` 明确区分三个预测器seed。
三组预测器分别评价，不自动合并成ensemble；seed间波动也不是生成器训练seed间的统计波动。

## 6. 监控与恢复

```bash
nvidia-smi
cat logs/newton_4g_6p_pipeline.pid
tail -n 80 logs/newton_4g_6p_pipeline.log
tail -f output/newton_4g_6p_20261003/logs/mp20_base.log
find output/newton_4g_6p_20261003 -name .complete
```

任务确已退出后，用同一启动命令和同一run-id恢复。成功标记的训练跳过，未完成训练按原目录中已有最佳checkpoint恢复，已存在生成文件跳过。
因为仓库训练入口不能正确解析 `last.ckpt`，本方案显式保留save_last=false；恢复可能回到较早最佳验证epoch，并不是最近一步的无损恢复。
只有checkpoint、没有.complete，不会被当作完整训练成功。

新一轮独立训练使用新run-id，例如：

```bash
python remote_workflow_newton/run_4g_6p.py all --run-id newton_4g_6p_second
```

## 7. 指标与限制

结构评价包括成分/几何有效性、覆盖率、密度及元素种类数的分布距离；性质评价包括FE/BG预测分布、目标误差、容差命中及联合命中。
上游结构评价要求至少1000个有效样本，若不足会报错。脚本记录该失败、继续执行性质评价，最后明确报告结构指标失败，不伪造完整结果。
三对预测器的性质结果是代理模型评价，不能作为DFT验证；本流程不训练RL，不执行DFT或MatGL弛豫，也不自动输出SUN物理稳定性指标。
服务器是否需要SLURM由实际GPU可见性决定：这里按已分配4090的Notebook shell运行，preflight会检查。如果CUDA不可见，先解决GPU分配。
没有真实远程执行结果前，不能确认你的4090环境已通过或长期训练不OOM。实际验证记录见同目录VALIDATION.md，明确区分本地GPU验证和服务器验证。
